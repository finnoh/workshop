# 👤 Curating your results

## MLflow: Your ML Experiment Manager

MLflow is a powerful open-source platform designed to manage the entire machine learning lifecycle. It provides essential tools for tracking experiments, logging parameters, metrics, and models, and organizing your work into runs and experiments. One of MLflow's greatest strengths is its ability to compare models visually, helping you make informed decisions about which approaches work best. It's also language-agnostic, supporting Python, R, and even LLM workflows, making it versatile for various research needs.

You can explore the [official MLflow documentation](https://mlflow.org/docs/latest/) for comprehensive details on all its features and capabilities.

## Why Choose MLflow?

### The Challenges Without Proper Tracking

Without a dedicated experiment management system like MLflow, machine learning workflows often become chaotic. Researchers typically struggle with messy code scattered across multiple scripts, making it difficult to track what was done in previous experiments. Reproducing results becomes nearly impossible as parameter choices and data preprocessing steps get lost over time. Metrics end up saved in random locations—sometimes in notebooks, other times in CSV files or simply printed to the console and lost forever.

### The Benefits of MLflow Integration

Integrating MLflow into your workflow brings immediate structure and clarity. It provides clean, consistent experiment tracking that makes every parameter choice, metric result, and model artifact easily accessible. Reproducibility becomes the default rather than an afterthought, as every experiment detail is automatically logged. The platform creates shareable and auditable workflows that facilitate collaboration and knowledge transfer within research teams. Best of all, MLflow works seamlessly whether you're running experiments locally on your laptop or scaling up to cloud infrastructure.

## Basic MLflow Usage

### Without MLflow: The Traditional Approach

Here's how a typical machine learning workflow might look without any experiment tracking:

```python
# Set parameters
n_estimators = 100
max_depth = 10

# Train model
rf_model = RandomForestClassifier(
    n_estimators=n_estimators, 
    max_depth=max_depth
)
rf_model.fit(X_train, y_train)

# Log metrics
train_accuracy = rf_model.score(X_train, y_train)
test_accuracy = rf_model.score(X_test, y_test)
```

In this approach, the parameters and results exist only within the script. If you run multiple experiments with different settings, you'll need to manually track everything or risk losing valuable information.

### With MLflow: Structured Experiment Tracking

Now let's see how the same workflow transforms when using MLflow:

```python
# Set parameters
# assisted by Cursor AI
import mlflow

# Set parameters
n_estimators = 100
max_depth = 10

# Start MLflow run
with mlflow.start_run():
    # Log parameters
    mlflow.log_param("n_estimators", n_estimators)
    mlflow.log_param("max_depth", max_depth)
    
    # Train model
    rf_model = RandomForestClassifier(
        n_estimators=n_estimators, 
        max_depth=max_depth
    )
    rf_model.fit(X_train, y_train)
    
    # Log metrics
    train_accuracy = rf_model.score(X_train, y_train)
    test_accuracy = rf_model.score(X_test, y_test)
    
    mlflow.log_metric("train_accuracy", train_accuracy)
    mlflow.log_metric("test_accuracy", test_accuracy)
    
    # Log model
    mlflow.sklearn.log_model(rf_model, "random_forest_model")
```

With MLflow, each experiment is wrapped in a "run" that automatically captures all the parameters, metrics, and artifacts you specify. This creates a comprehensive record that you can reference later, compare with other runs, and use to reproduce your results exactly.

## MLflow for Econometrics Research

MLflow isn't just for traditional machine learning—it's equally valuable for econometric research. You can use it to track different identification strategies, compare metrics across various model specifications, and analyze results across different sub-samples.

Here's an example of using MLflow with instrumental variables regression:

```python
# assisted by Cursor AI
import mlflow
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_squared_error, r2_score
import statsmodels.api as sm
from statsmodels.sandbox.regression.gmm import IV2SLS

# Generate data
ddData = generate_iv_data(n_samples=2000)

# Split data
train_data, test_data = train_test_split(ddData, test_size=0.2, random_state=42)

# Start MLflow run
# NOTE: Perhaps smarter as an experiment? Different configs as runs?
with mlflow.start_run(run_name="IV_Regression_Example"):
    
    # Log data generation parameters
    mlflow.log_param("n_samples", 2000)
    mlflow.log_param("model_type", "IV2SLS")
    
    # Fit OLS model (naive approach)
    ols_model = sm.OLS(train_data['y'], sm.add_constant(train_data['x']))
    ols_results = ols_model.fit()
    
    # Fit IV model
    iv_model = IV2SLS(train_data['y'], 
                     sm.add_constant(train_data['x']), 
                     train_data['z'])
    iv_results = iv_model.fit()
    
    # Make predictions
    X_test_const = sm.add_constant(test_data['x'])
    ols_predictions = ols_results.predict(X_test_const)
    iv_predictions = iv_results.predict(X_test_const)
    
    # Calculate metrics
    ols_mse = mean_squared_error(test_data['y'], ols_predictions)
    iv_mse = mean_squared_error(test_data['y'], iv_predictions)
    ols_r2 = r2_score(test_data['y'], ols_predictions)
    iv_r2 = r2_score(test_data['y'], iv_predictions)
    
    # Log metrics
    mlflow.log_metric("ols_coefficient", ols_results.params[1])
    mlflow.log_metric("iv_coefficient", iv_results.params[1])
    mlflow.log_metric("ols_mse", ols_mse)
    mlflow.log_metric("iv_mse", iv_mse)
    mlflow.log_metric("ols_r2", ols_r2)
    mlflow.log_metric("iv_r2", iv_r2)
    
    # Log model summary as artifact
    with open("ols_summary.txt", "w") as f:
        f.write(str(ols_results.summary()))
    
    with open("iv_summary.txt", "w") as f:
        f.write(str(iv_results.summary()))
    
    mlflow.log_artifact("ols_summary.txt")
    mlflow.log_artifact("iv_summary.txt")
    
    # Log custom tags
    mlflow.set_tag("estimator_type", "instrumental_variables")
    mlflow.set_tag("endogeneity", "corrected")
    
    print(f"OLS coefficient: {ols_results.params[1]:.4f}")
    print(f"IV coefficient: {iv_results.params[1]:.4f}")
    print(f"True coefficient: 2.5000")
```

This example demonstrates how MLflow can track both OLS and IV approaches to the same problem, logging their respective coefficients, prediction errors, and model summaries. By organizing this information within MLflow, you can easily compare the performance of different econometric techniques and maintain a clear record of your analytical process.
